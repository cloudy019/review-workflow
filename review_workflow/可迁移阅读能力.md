# Codex / WorkBuddy 单篇阅读能力

本文保留旧能力包的迁移记录。当前生产入口已统一为 Evidence Loop，见 `文献知识库/EvidenceLoop统一阅读入口.md`；已安装的 `paper-review` 也已改为框架兼容入口。下文的旧包命令只用于旧格式任务恢复，不作为新任务流程。

两端共用 `paper-review` 技能。AI理解和写作由当前宿主模型完成；Python抽取原文、处理图片并渲染离线评审页。是否支持子代理只影响并行方式，不影响单篇阅读能力。

## 已安装入口

Codex：用户技能目录中的 `paper-review/SKILL.md`。WorkBuddy：本项目 `.workbuddy/skills/paper-review/SKILL.md`。二者来自同一能力包，包含 `nature-reader`、`nature-shared`、`deeppapernote` 和按论文类型调用的专项技能，嵌套依赖通过任务中的路径直接读取，无需宿主逐个发现。

在任一宿主中使用：

> 使用 paper-review 技能接续当前批次的AI阅读并生成评审页。按台账选择已有reading任务，每篇只读一个PDF、只写自己的隔离目录；完成后串行登记，交给我做八节人工评审。

主任务读取台账和批次，单篇任务用 `prepare-reading-task <job-id> --engine codex|workbuddy` 准备。若由另一端接续，先停止原执行者再加 `--handoff`。渲染后由主任务 `accept-reading-output <job-id>` 登记；人工提交后仍需项目原有导入步骤。

## 迁移操作

复制 `artifacts/portable-paper-review/paper-review/` 整个文件夹，或解压同目录的能力包压缩文件。在目标机器从包内运行：

```powershell
python paper-review/scripts/review.py install --engine both --project <项目根目录>
python -m pip install -r paper-review/requirements.txt
python paper-review/scripts/review.py doctor
```

必须使用目标宿主实际执行的Python；可以装到该宿主的虚拟环境。需要自定义安装位置时，指定单一 `--engine` 并加入 `--target <目标技能目录/paper-review>`。无需原项目源码、原用户目录或原Codex插件即可使用已核验的本地PDF。

新项目先配置自己的 `review-project.json`、单篇job和来源路径；沿用本项目时，Zotero来源准备仍由规定的插件层完成。能力迁移不搬运私人文库或替用户作人工判断。现有job包含本机绝对路径，迁移项目数据时须更新这些路径，再生成新的reading-task。

能力检查核对资源、Python和PyMuPDF；真实阅读还需要宿主当前模型能够读取文件、执行命令和写入任务目录。结果文件只表示AI材料已完成，登记后状态是 `human_reviewing`。

当前非交互WorkBuddy验收已加载技能，但Bash和PowerShell被其权限审查拒绝，尚未生成评审页。应在WorkBuddy的交互会话中正常批准阅读器所需的文件读取、项目内命令执行和隔离目录写入；希望一键非交互执行时，须由用户在WorkBuddy权限设置中授权对应操作。能力包安装不修改宿主权限设置，不加入跳过权限审查的参数。

项目桥接配置 `review-app/workbuddy/workbuddy-bridge.json` 支持可选的 `allowed_tools` 列表，用于传递用户已经明确授予的工具权限；默认空列表。本次没有填入工具授权。非交互启动以项目根目录为工作目录，技能与产物均置于该项目内。
