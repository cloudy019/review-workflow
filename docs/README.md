# docs

> 精简上下文四片。**新 agent 按 1 → 2 → 3 → 4 的顺序读**，不要一次读完全部。

| 顺序 | 文件 | 读它的时机 |
|---|---|---|
| 1 | `CONTRACTS.md` | 动手前必读：批次边界、状态协议、八节与许可、哈希锚点、图表裁切、目录、命令、验证判据、白名单 |
| 2 | `DECISIONS.md` | 想知道「为什么这样设计」时：9 条决策，含被否决方案 |
| 3 | `RISKS.md` | 接手或交付前：未闭合风险与待办 |
| 4 | `OPEN.md` | 怀疑文档与代码不一致时：待复核项与已处理冲突 |

## 维护规则

- 修 bug 的**决策与理由**追加到 `DECISIONS.md`；未闭合项追加到 `RISKS.md`。
- 文档与代码冲突时，以代码为准，并在 `OPEN.md` 记录冲突与处理方式。
- 契约变更（字段、状态、哈希锚点、白名单）先改 `CONTRACTS.md`，再改代码。
- 不再新增并列的过程文档；新的说明优先并入这四片。
