# 关键决策与理由

> 由原 `CHANGELOG.md` 蒸馏。每条保留「决策 / 理由 / 否决方案」，过程叙事与逐次验收计数已丢弃；需要复现证据时查 `git log` 或本地归档。

## 1. 中文稿：删掉强制分页，按比例限高

- **决策**：删除图片段落的 `page_break_before` 与图注后的 `add_page_break()`；按 PNG 比例限高 5.4 英寸；引出段、图片、图注分别加 `keep_with_next` / `keep_together`。
- **理由**：图必须跟在引用它的正文之后、与图注同页；固定 6.4 英寸宽会让图高达 6.4–6.8 英寸，即使不分页也塞不进一页。
- **否决**：保留强制分页只缩图片——仍会把图推到独立页，问题不变。

## 2. 误检型 `omit` 不参与图卡配对

- **决策**：新增负向理由正则；`omit` 且理由为「误检 / 重复 / 纯文字引用」时整行跳过，不占用任何裁图。
- **理由**：决策 `id` 是「该页第几条」而非图号，配对只能靠理由里的图号；负向描述同样含图号，会先于真实决策抢到核心图表。
- **否决**：按 `pN-fM` 序号配对——会把「不作正文图」徽标打到真正的图 1 上。

## 3. 零图页面必须写明原因，并守住「只看图」

- **决策**：无裁图时在正文最前输出「图表缺失」说明；「只看图」在零图时保留全部速读分区、滚到说明处，按钮改标「图表缺失」。
- **理由**：静默留白违反「无法提取必须写明原因」；旧实现 `section.hidden = !figures` 会把每一节都藏掉，只剩空白页。
- **否决**：隐藏按钮或允许空白页——用户无从判断是没图还是渲染失败。

## 4. AI 核验登记前加视觉证据门禁

- **决策**：登记前校验图表决策数、可用裁图数、`visual_review`、`html_visual_qa.status`；只有带 `approved_by` / `reason` / `approved_at` 的人工签署豁免可绕过，并写入 `ai_verification_gate`。
- **理由**：原实现只校验报告格式，零裁图 + `pending` 仍能登记成 `ai_verified`，等于把「没看图」记成「已核验」。
- **否决**：只校验报告字段；或静默放行——两者都会制造虚假合规。

## 5. 测试断言对齐 v2 模板，而不是删测试

- **决策**：逐条按现行模板契约更新 10 项旧断言（判定标签、导出表达式、筛选 dataset、灯箱、草稿恢复）。
- **理由**：失败全部来自模板改版后的文案/结构变化，长期失败会掩盖真实回归。
- **否决**：删除失败测试——会同时丢掉 XSS、离线、外链安全检查。

## 6. 批量裁图只从原 PDF 真实区域生成

- **决策**：新增批量裁图工具，逐图裁切并做身份核验；只写 `verified=true` 的 PNG，缺失项写具体原因。
- **理由**：该批任务只落了「意图清单」，没有可显示的裁图资产；整页图被模板与验证器禁止显示，无法兜底。
- **否决**：用整页 `source-pages` 兜底；或重绘/美化图表——前者不是单图，后者伪造证据。

## 7. 每张已验证裁图各出一张图卡

- **决策**：`_collect_figures()` 以裁图资产为准，`figure_decisions` 降级为标注（按图号 + 页码 ±1 认领，认领不到用清单里的原 PDF 图题兜底）。
- **理由**：同一句样板理由被复用 18 次时，一张裁图会占掉全部决策；裁图本身已通过身份核验，不应因决策缺失而消失。
- **否决**：继续把决策当唯一白名单——会漏显正式裁图，也会按决策条数误报缺图。

## 8. 视图层重渲染：校验后重绑定，不无条件写回

- **决策**：新增 `--rebind-ai-view`；先逐字节校验除 `paper-review.html` 外的所有 AI 核验输入，全部未变才同步页面哈希，并写 `view_rebind_log`。
- **理由**：`reading_receipt.artifacts` 与 `ai_citation_permission.bound_artifacts` 是两本账，只更新一本会让 `ai_verified` 掉到 `needs_clarification`；无条件重绑又会掩盖其它输入被改。
- **否决**：不更新绑定（许可失效）；无条件重绑（等于放弃校验）。

## 9. 服务端 404：验证日志链，不改归档

- **决策**：`ai_review_content()` 只在「唯一差异是 `artifact_sha256`、`view_rebind_log` 从归档页面哈希连续接到当前落盘哈希、其余产物与 key 集合完全一致」时豁免。
- **理由**：这是第三本哈希账，归档里存着核验当时的页面哈希；不改归档才能保住证据，不改校验才能防篡改。
- **否决**：改写 `ai_reviews/archive/*.json`（伪造核验记录）；或放宽服务整体校验（任何页面改动都能过）。

## 已取代

- 旧「可迁移阅读能力包」文档（`review_workflow/可迁移阅读能力.md`）已被 Evidence Loop 统一入口取代：单篇阅读、页面生成与人工状态统一走 `evidence_loop issue/submit/serve`，旧包命令只用于旧格式任务恢复。原文件已清理。

## 10. 主张区：从纯文字卡改为「文字 + 对应页的图 + AI 判断」

- **决策**：claims 按 `source_pages` 首个页码排序；每条挂上该页最多 2 张已验证裁图；每条显示一句 AI 判断（原文陈述 / AI 推断各自的引用边界）；模板改三列 grid，灯箱覆盖主张区。
- **理由**：主张只有文字时，读者看不到它依据什么，只能靠「不表明 / 不代表」自我防御；页码本来就在数据里，却没被用上。
- **否决**：只加图不排序（仍无法按论文顺序核对）；把判断写成模板套话（等于没判断）。

## 11. 提示词约束候选主张用肯定句

- **决策**：`prompts/read.md` 增加规则：主张写「这篇论文说了什么、能支撑什么」，限定条件与反例放 `limitations`，不在主句堆「不表明 / 不代表」。
- **理由**：旧提示词只要求「标注页码」，模型自由发挥成否定式套话，信息增益低。
- **边界**：只影响新任务。已读任务的 claims 是哈希锚点，要改必须 `reopen` 重读并作废现许可，不能原地改写。

## 12. 取消「主张」独立页，并入速读正文

- **决策**：删除 `data-pane="claims"` 标签与 `pane-claims` 容器；候选主张作为正文最后一节（`data-summary-topic="claims"`）渲染；只保留「速读」一个标签。
- **理由**：主张是速读的证据层，不是并列的第二份材料；分页会让读者在「看内容」和「看主张」之间来回切换，而右侧边栏本来就在承担判断。
- **否决**：保留双页但默认打开主张（仍要切换）；把主张塞进右侧评审卡（右栏已被八节占满）。
- **代价**：候选主张节在「速览 / 方法 / 结果」筛选下会隐藏，只在「全部」可见。
